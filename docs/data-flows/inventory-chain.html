InventoryService.post_movement() (app/services/inventory/inventory_service.py) is the ONE primitive every stock-moving action in this entire app calls through — never its own ad-hoc arithmetic. product.stock_qty_cache is written ONLY here, in the same DB transaction as the stock_ledger_entry insert that justifies it. The ledger is append-only (a genuine BEFORE UPDATE/ DELETE trigger — migration 0011 — rejects any later UPDATE, the same discipline as audit_log). Only the 4 Manual actions below also post to Accounting — every other caller (8 document types across Sales + Purchase) moves stock with zero accounting side-effect, by design.

Side-Effects
Accounting

AccountingPostingService.post_opening_stock() (DR Inventory / CR Opening Balance Equity) · post_stock_increase() (DR Inventory / CR Stock Adjustment) · post_stock_decrease() (DR Stock Adjustment / CR Inventory).

Skipped entirely (no journal) when the resolved cost is 0 — never a fabricated/zero-value entry. The Sales/Purchase document chains above are completely unaffected by this — only these 4 manual actions call these 3 new methods.

💡 Cost resolution rule: Opening Stock sets the cost basis outright. Stock In / Adjustment-IN blend the entered cost into the running average (new_avg = (old_qty·old_avg + new_qty·new_cost) / (old_qty+new_qty)) — or, if no cost is entered, fall back to the current average unchanged. Stock Out / Adjustment-OUT always value at the current average and never change it.
