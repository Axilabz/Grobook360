🧾 Sales Chain — Data Flow

Index Sales Purchase Payments Inventory Payroll Accounting/GST Reports
Estimate → Sales Order → Delivery Challan → Sales Invoice is the full document chain; Sales Return and Credit/Debit Note both branch off a POSTED Sales Invoice. Only 3 of these 6 document types ever move stock (Delivery Challan, direct Sales Invoice, Sales Return); only 2 ever touch Accounting + GST (Sales Invoice, Sales Return, Credit/Debit Note). E-Invoice/E-Way Bill generation is always a separate, manual action — never triggered automatically by posting the invoice.

4 Sales Invoice — Post
The authoritative billing transaction — triggers Accounting + GST in the SAME transaction
Frontend
SalesInvoiceManagement.tsx

"Post Invoice" on a DRAFT invoice (Owner/Manager only — Salesperson can create/edit/cancel a draft but never post).

API Endpoint
POST /sales/invoices/{invoice_id}/post

Router: app/api/v1/sales_invoices.py

Service Method
SalesInvoiceService.post_invoice()

app/services/sales/sales_invoice_service.py:642-752 — branches on invoice_type.

Database
sales_invoicesales_invoice_linedelivery_challan_line

Status DRAFT → POSTED (immutable from here); if DC-based, delivery_challan_line.invoiced_quantity incremented instead of moving stock again.

Side-Effects (in exact order)
  1. IF DIRECT_SALES_INVOICE: Stock Ledger InventoryService.post_movement(STOCK_OUT, source_type=SALES_INVOICE) per line. IF DELIVERY_CHALLAN_SALES_INVOICE: none — the Challan already moved it.
  2. Accounting AccountingPostingService.post_sales_invoice() — DR Accounts Receivable / CR Sales Revenue + Output CGST/SGST/IGST → real journal_entry/journal_line rows.
  3. GST GstReportingService.record_invoice_transaction() — writes gst_transaction/gst_transaction_line (positive sign).
  4. Audit AuditService.record("SALES_INVOICE_POSTED")

All 4 steps run inside post_invoice() itself — one DB transaction, not a queue or async step.

↘ Separate, manual action from the invoice's own detail screen — never auto-triggered by posting
