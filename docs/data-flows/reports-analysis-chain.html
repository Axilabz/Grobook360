🔎 Reports & Analysis (Read Path) — Data Flow

Index Sales Purchase Payments Inventory Payroll Accounting/GST Reports
Every page on this site so far is a WRITE path. This one is the opposite: Reports, Analysis, and the Dashboard never write anything — they are live SQL aggregations over the already-authoritative tables every other chain produces. Zero new business tables were ever introduced for reporting — this is a structural rule, not a convention: no persisted/materialized report table, no recalculated business/accounting/GST value a source module already computed.

Read Analysis (interactive BI layer)
A thin composition layer OVER Reports — never a second formula implementation
Frontend
AnalysisManagement.tsx

Overview/Sales/Products/Customers/Purchases/Inventory tabs — Period + Compare-To filters, charts, drill-down, Sales-by-User table.

API Endpoint
GET /analysis/overview/sales/sales-by-user/products/customers/purchases/inventory

Router: app/api/v1/analysis.py — gated by the SAME reports.view_* codes Reports uses, no dedicated Analysis permission family.

Service Method
AnalysisService.get_*()

app/services/analysis/analysis_service.py — calls SalesReportService/PurchaseReportService/etc. TWICE (current period + comparison period) and merges into {current, previous, change, change_percent}. Trend series are the ONLY genuinely new query logic (GROUP BY date_trunc(...)).

Reads From

Same tables as the equivalent Reports family above, plus sales_invoice.created_by (joined to user.name) for Sales-by-User.

Side-Effects

None — but Sales-by-User is the one place a read path enforces a data-scope rule server-side: a Salesperson's own request is filtered to created_by == their own user_id; Owner/Manager see every staff member.

⚠ Fields with NO approved calculation anywhere in this codebase always render as an explicit {"value": null, "reason": "..."}, never a fabricated number: Inventory Value, Gross Margin/Gross Profit, and Stock Turnover. (Note: product.cost_price now has a REAL meaning as of the Weighted Average Cost feature — see the Inventory page — but no report has been updated to use it for a margin calculation; that remains an explicit, unapproved Open Decision.)
